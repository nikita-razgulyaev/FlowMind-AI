# Данные между шагами

Почти любой сценарий передаёт данные от шага к шагу: найденный номер заказа попадает в ответ клиенту, ответ нейросети отправляется в Telegram, поле из ответа сервиса записывается в таблицу. FlowMind AI позволяет делать это **без ручного набора ссылок**.

## Откуда берутся данные

В списке доступны только шаги, которые **соединены с текущим выше по цепочке**. Они показываются в порядке близости: первым идёт тот, что стоит прямо перед текущим. Шаг, который ни с чем не соединён, в списке не показывается: его данные в момент выполнения ещё не готовы.

Шаги запуска показывают свои данные запуска: например, у шага **Сообщение в Telegram** это текст сообщения, чат и имя клиента.

## Два вида полей

### 1. Поля, где нужна только ссылка

Это поля, в которых указывается, **что обрабатывать или проверять**: исходный текст в «Обработке текста», значение в «Выборе варианта», «Что проверяем» в «По ключевым словам», левая часть правила в простом условии.

Вместо ввода от руки здесь **выпадающий список**:

- По умолчанию выбран **шаг, стоящий перед текущим**.
- Если шаг ни с чем не соединён, написано **«Нет соединённых шагов»**.
- Если у шага несколько полей (например, у «Запроса к сервису» это данные ответа, текст ответа и код ответа), рядом появляется второй список **«какие данные»**.
- Пункт **«Ручной ввод»** оставляет обычное поле, где можно указать ссылку самому, например `{input}`. Это удобно в сценариях с большим количеством похожих шагов.

::: info Автоматическое слежение
Пока вы не выбрали шаг сами, значение следует за предыдущим шагом: переставили связь, и поле обновилось. Как только вы выбрали шаг или ручной ввод, значение зафиксировано.
:::

### 2. Текстовые поля со вставками

Это поля, где вы пишете текст и в него нужно подставить данные: задание нейросети, текст сообщения или письма, адрес и тело запроса, значения для таблицы, поля календаря.

В самом поле только ваш текст. **Под ним** находится строка вставки:

1. Выпадающий список шагов (по умолчанию предыдущий).
2. Если у шага несколько полей, второй список с их названиями.
3. Кнопка **«Вставить»**.

Поставьте курсор в нужное место текста, выберите данные и нажмите **«Вставить»**: в позицию курсора добавится ссылка. Под полем вставленные ссылки отображаются понятными подписями, например «Запрос к сервису → json → rates → RUB». Если подпись красная, ссылка ведёт на шаг, которого нет.

## Как это записано внутри

Ссылка выглядит как `{id_шага}` или `{id_шага.поле}`, где `id_шага` — внутреннее имя шага (например, `http_1`), а путь к полю составляется из ключей через точку. Номера элементов списка записываются в квадратных скобках: `{id.items[0].name}`.

Данные запуска записываются просто по имени: `{input}`, `{email_subject}`.

::: warning Имя шага должно совпадать точно
Если вы пишете ссылку вручную, имя в скобках должно совпасть с id шага **буква в букву** (регистр и подчёркивания). Проще не набирать ссылки, а вставлять их кнопкой. Если ссылка ведёт на несуществующий шаг, [проверка сценария](/guide/checking) покажет ошибку.
:::

## Реальные значения из прошлого запуска

После первого запуска сценария в выпадающих списках рядом с полями отображаются **примеры реальных значений**: «например: 91.5». Для ответа сервиса список полей раскладывается по структуре JSON-ответа, поэтому нужное поле можно выбрать кликом, а не угадывать его название.

## Ответ сервиса: структура

Шаг **«Запрос к сервису»** сохраняет результат с полями:

| Поле | Что внутри |
|---|---|
| `.status_code` | Код ответа (200, 404 и т. д.) |
| `.body` | Текст ответа |
| `.json` | Данные ответа в виде структуры, если сервис вернул JSON |

Например, курс из ответа `{"rates": {"RUB": 91.5}}` доступен как `{id_шага.json.rates.RUB}`.
