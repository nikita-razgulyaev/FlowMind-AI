# Архитектура

## Общая схема

```text
Браузер ──► Редактор сценариев (React)
              │  HTTP /api/*
              ▼
        FastAPI (backend)
        ├─ Авторизация, пользователи, тарифы, оплата
        ├─ Сценарии, шаблоны, история запусков
        ├─ Движок выполнения сценариев (WorkflowEngine)
        ├─ ИИ-помощник и клиент языковых моделей
        └─ Фоновые задачи: расписание, почта, Telegram
              │                       │
              ▼                       ▼
     SQLite / PostgreSQL     Внешние сервисы: Telegram, Google, Яндекс,
                             Mail.ru, ЮKassa, провайдеры LLM, Ollama
```

Один процесс бэкенда раздаёт API (`/api`), собранное приложение (`/`) и эту документацию (`/help/`). Благодаря этому сервис запускается одним контейнером.

## Модель данных

Основные таблицы:

| Таблица | Назначение |
|---|---|
| `users`, `refresh_tokens`, `email_tokens` | Пользователи, токены обновления, токены подтверждения почты и сброса пароля |
| `plans`, `subscriptions`, `payments`, `usage_counters`, `global_counters` | Тарифы, подписки, платежи, счётчики использования по месяцам, глобальные счётчики |
| `workflows` | Сценарии: шаги и связи хранятся в JSON, признак включения, владелец |
| `executions` | Запуски: статус, источник, время, журнал по шагам |
| `connections` | Подключения с зашифрованными секретами |
| `telegram_updates` | Обработанные обновления Telegram (защита от повторов) |
| `app_settings`, `audit_log` | Глобальные настройки и журнал действий администраторов |

## Как выполняется сценарий

1. **Запуск.** Событие (кнопка, Telegram, письмо, ссылка, расписание) создаёт запись в `executions` и передаёт данные запуска в движок. Перед этим проверяются лимиты тарифа и число одновременных запусков.
2. **Порядок шагов.** Движок строит порядок выполнения по связям (топологическая сортировка) и последовательно выполняет шаги.
3. **Данные.** Результат каждого шага сохраняется в общем контексте. В тексте шагов `{id}` и `{id.поле}` подставляются из контекста до выполнения.
4. **Ветвление.** Шаги «Условие», «Выбор варианта» и «По ключевым словам» выбирают ветку, шаги остальных веток пропускаются.
5. **Агент.** Шаг «ИИ-агент» запускает цикл: модель решает, вызвать ли инструмент (шаг, связанный с агентом), получает результат и продолжает, пока не даст ответ или не исчерпает число итераций.
6. **Завершение.** Движок записывает статус и журнал. Выполнение ограничено по времени и поддерживает остановку.

## ИИ-помощник

Помощник получает описание задачи и текущий сценарий, а языковая модель возвращает граф в формате JSON. Бэкенд **проверяет и нормализует** его: отбрасывает неизвестные типы шагов, исправляет связи, подставляет значения по умолчанию, исправляет искажённые имена шагов в ссылках и раскладывает шаги на холсте. Только после этого граф отправляется в редактор, где пользователь применяет его вручную.

## Языковые модели

Запросы к моделям идут через единый клиент:

- **Local**: Ollama на компьютере пользователя.
- **Cloud**: либо подключение пользователя (OpenAI-совместимое), либо **цепочка моделей платформы**: основная и запасные. При сбое или пустом ответе клиент переключается на следующую модель, а проблемная откладывается на время (при повторных сбоях время растёт, максимум 10 минут).

## Фронтенд

Редактор построен на React Flow: шаги и связи хранятся в состоянии, из которого формируется JSON сценария. Данные между шагами (списки выбора, подписи ссылок, значения из прошлого запуска) считаются на клиенте модулем `utils/stepData.ts`, а проверка сценария выполняется модулем `utils/validateWorkflow.ts`. История изменений графа (отмена и повтор) ведётся хуком `useGraphHistory`.
