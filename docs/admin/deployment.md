# Публикация в облаке

Облачный режим (`DEPLOYMENT_MODE=cloud`) включает регистрацию, тарифы, оплату и административную панель. Образ собирается из корневого `Dockerfile`: в нём собирается фронтенд и документация, а бэкенд раздаёт их вместе с API.

## Вариант 1. Свой сервер (Docker Compose + HTTPS)

Подходит для виртуального сервера с публичным IP и доменом. Запускаются приложение, PostgreSQL и Caddy: он сам получает сертификат HTTPS.

1. Направьте A-запись домена на IP сервера.
2. Скопируйте пример настроек и заполните его:

   ```bash
   cp .env.prod.example .env.prod
   ```

   Обязательно задайте `DOMAIN`, `POSTGRES_PASSWORD`, `SECRET_KEY`, `ENCRYPTION_KEY`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`. Значения для секретов удобно получить командой:

   ```bash
   python -c "import secrets; print(secrets.token_urlsafe(48))"
   ```

3. Запустите:

   ```bash
   docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
   ```

4. Откройте `https://ваш-домен` и войдите под администратором.

Порт приложения наружу не публикуется: весь трафик идёт через Caddy (порты 80 и 443). Документация будет доступна по адресу `https://ваш-домен/help/`.

## Вариант 2. Render

В репозитории есть файл `render.yaml` (Blueprint): один Docker-сервис (API и сайт) и база PostgreSQL.

1. В Render выберите **New → Blueprint** и укажите репозиторий.
2. Значения, помеченные как секретные, Render спросит при создании.
3. После первого запуска проверьте адрес `/api/health`.

::: warning Бесплатный план Render
Бесплатный сервис «засыпает» после простоя, а бесплатная база данных имеет ограниченный срок жизни. Для постоянной работы выберите платные планы, а перед демонстрацией «разбудите» сервис.
:::

## Что нужно настроить после запуска

| Задача | Где |
|---|---|
| Реальная оплата вместо демонстрационной | `PAYMENT_PROVIDER=yookassa` и данные магазина: [оплата](/admin/configuration#оплата) |
| Письма (подтверждение почты, сброс пароля) | Переменные `SMTP_*` |
| Вход через Google, Яндекс, Mail.ru в подключениях | [OAuth](/admin/configuration#oauth-google-яндекс-mail-ru) |
| Модели платформы для нейросети | `PLATFORM_LLM_PROVIDERS` и ключи |
| Тарифы, лимиты, цены | [Админ-панель](/admin/administration) |

## Резервное копирование и обновление

- **База данных:** регулярно делайте копии PostgreSQL (`pg_dump`) или тома `pgdata`.
- **Ключи:** сохраните `SECRET_KEY` и `ENCRYPTION_KEY`. Без `ENCRYPTION_KEY` сохранённые подключения будут недоступны.
- **Обновление:** `git pull` и повторный `docker compose ... up -d --build`. Миграции базы применяются автоматически при старте.

## Проверка работоспособности

Сервис отвечает на `GET /api/health`: `200`, если база данных доступна, и `503` при проблемах. Этот адрес удобно использовать как health-check в хостинге или мониторинге.
