# Разработка и тесты

## Окружение

Запуск из исходников описан в разделе [установка](/admin/installation#запуск-из-исходников). Для разработки нужны Python 3.12, Node.js 22 и (необязательно) Docker.

## Тесты бэкенда

```bash
cd backend
pip install -r requirements.txt
pip install pytest pytest-asyncio
python -m pytest -q
```

Тесты используют временную базу данных и не обращаются к внешним сервисам. Часть тестов помечена как «только локальный режим» и пропускается в облачной конфигурации.

| Область | Что проверяется |
|---|---|
| Выполнение сценариев | Порядок шагов, ветвление, подстановка данных, ошибки шагов, остановка |
| Ветвление и шаги без нейросети | Условия по правилам, классификация по словам, сборка текста, расширенная обработка текста |
| Нейросеть | Переключение на запасную модель, цепочка провайдеров, пустые ответы |
| ИИ-помощник | Проверка графа, нормализация, исправление ссылок на шаги |
| Облачный режим | Регистрация, вход, подписки, платежи, лимиты тарифов, администрирование |
| Подключения и безопасность | Шифрование секретов, OAuth, защита от SSRF, ограничения частоты |
| Telegram и почта | Приём сообщений, повторные обновления, ответы |

::: warning Известная проблема тестов оплаты
Девять тестов в `tests/test_cloud_billing.py` ожидают, что демонстрационная оплата завершается сразу (`succeeded`), а текущая реализация переводит платёж из `pending` в оплаченный через 10 секунд. Тесты нужно привести в соответствие с этим поведением (например, ждать завершения платежа). На работу сервиса это не влияет.
:::

## Тесты фронтенда

```bash
cd frontend
npm install
npm test            # Vitest
npx tsc -b          # проверка типов
npm run build       # сборка
```

Проверяются вспомогательные модули редактора: данные между шагами, выбор шага по умолчанию, проверка сценария, история отмены, текстовые операции.

## Документация

```bash
cd docs
npm install
npm run dev         # http://localhost:5174/help/
npm run build       # сборка в docs/.vitepress/dist
```

Страницы это Markdown-файлы в папке `docs/`. Меню настраивается в `docs/.vitepress/config.mts`, цвета в `docs/.vitepress/theme/custom.css`. В Docker-образе сайт собирается автоматически и публикуется по адресу `/help/`.

## Как добавить новый шаг

1. **Бэкенд.** Добавьте обработчик `_handle_<тип>` в `backend/app/worker.py` и зарегистрируйте его в словаре обработчиков. Если у шага несколько выходов-веток, обработайте его в `_register_branch`. Добавьте тип в список допустимых типов ИИ-помощника (`services/ai_assistant.py`) и его описание в системный промпт.
2. **Фронтенд.** Добавьте тип в `types/workflow.ts`, внешний вид карточки в `NODE_META` (`components/canvas/CanvasNode.tsx`), кнопку на палитре (`NodePalette.tsx`), описание и пример в `utils/glossary.ts`, форму настроек в `NodeConfigPanel.tsx`, значения по умолчанию в `WorkflowEditor.tsx` и правила в `utils/validateWorkflow.ts`.
3. **Данные шага.** Если шаг возвращает поля, опишите их в `utils/stepData.ts`, чтобы они появились в списках выбора.
4. **Документация и тесты.** Добавьте страницу в справочник и тест обработчика.

## Правила кода

- Бэкенд: Python, типы аннотируются, длинные операции асинхронные, секреты не попадают в журнал и ответы.
- Фронтенд: TypeScript, компоненты функциональные, логика, не связанная с отображением, выносится в `utils/` и покрывается тестами.
- Тексты интерфейса и сообщения об ошибках на русском, понятные пользователю, без технических подробностей.
